Databases

A database is a collection of records with properties you choose. Every record is also a page with room for its own notes, and the same records can be seen in as many views as you like.

Records are pages

Open any record to write in it like any other page: headings, checklists, images, even another database. Its properties sit at the top. Records link, tag and show up in search exactly like pages do, which is why a task can mention a design note and the note lists the task under Linked to this page.

Put a database anywhere with the Database view block, or give it a page of its own. Grids stay fast with thousands of records: rows are loaded in pages and only the visible ones are drawn.

Property types

Eighteen types cover text, numbers, choices, dates, contact details and computed values:

  • Title
  • Text
  • Number
  • Select
  • Multi-select
  • Status
  • Date
  • Checkbox
  • URL
  • Email
  • Phone
  • Created time
  • Updated time
  • Unique ID
  • Relation
  • Rollup
  • Formula
  • Button

Status groups its options into to-do, doing and done groups, which boards and progress rollups understand. Unique IDs number records with an optional prefix. Buttons run an automation when clicked.

Relations and rollups

A relation links records in one database to records in another, or the same one, and the link shows on both sides. Tasks belong to projects; a project lists its tasks. Relations within one database model subtasks and dependencies.

A rollup reads through a relation and summarises what it finds: count, count unique, sum, average, min, max, earliest, latest, percent checked or percent done. That last one gives a project its live progress bar from the status of its tasks.

Formulas

Formula properties compute a value from other properties, with a live preview as you write. The language covers logic, maths, text and dates:

Filter, sort and group

Filters combine conditions with AND and OR groups. Sort by several properties at once. Group records by a property, with one level of subgroups, and collapse the groups you don't need. Each view keeps its own filters, sorts, grouping and visible columns.

Working in the grid

The table is built for the keyboard. Arrow keys move between cells, Enter or F2 edits, Delete clears, and Shift Enter opens the record. Ctrl Space selects rows, Ctrl A selects all loaded rows, and a bulk bar then edits, duplicates or trashes them together. Screen readers hear each selection change.

Record templates

Give a database templates for its records: a bug report with steps to reproduce, a meeting note with an agenda, a task with a checklist. New records can start from a template, and automations can create records from one.

Project starters

New from template builds a complete project in one step, with example records you can keep or delete:

Project Manager
Projects, Milestones, Sprints and Tasks, wired together with subtasks, dependencies and live progress.
Task Tracker
One Tasks database with subtasks, dependencies, a board, a calendar and a timeline.
Software Project
The Project Manager setup plus a task Type (feature, bug, chore) and a Bugs view.

Projects made this way also register themselves with the command palette's Create task in project, so you can add a task to any project from anywhere.
